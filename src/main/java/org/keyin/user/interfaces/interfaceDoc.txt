








        Interfaces can be used to implement constraints that MUST have certain methods or roles to access restrictions.
        They are used in between classes and roles to allow contracts between one another and not leak over object created boundaries.
        In the Employee case the system will make sure the employee is able to generate a ticket.

        Interfaces in general are for anyone who wants readable code with decision making intact.
        The class defines how each method will work by using interfaces.

        In this project we just used the interface to set constraints on management.
        But in the real world it makes the project much more stable and flexible.

        Compilers using interface enforce this constraint, interfaces have no code inside the methods they are using.
        They just take in the signature of the method. The class that this directs to will implement that logic.

                That is my grasp on interfaces.
